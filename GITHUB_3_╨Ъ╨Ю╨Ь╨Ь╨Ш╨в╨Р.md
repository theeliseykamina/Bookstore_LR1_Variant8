# GitHub: обязательный пункт лабораторной

По методичке исходный код должен быть загружен в GitHub (или Bitbucket); в отчёте нужна ссылка. Требуется **минимум 3 реальных коммита в разное время**, не через веб-интерфейс GitHub и не с разницей в пару часов.

## Самый простой вариант: GitHub Desktop

1. Установи приложение **GitHub Desktop**: https://desktop.github.com/ . Авторизуйся в GitHub.
2. Распакуй проект. Через **File -> Add local repository** выбери папку проекта. Если репозитория нет, GitHub Desktop предложит создать его.
3. **Первый день:** отметь только файлы `src/*.h`, `src/*.cpp` и `Bookstore_LR1.cbp`. Commit message: `Созданы классы товаров и контейнер Keeper`. Нажми **Commit to main**, затем **Publish repository**.
4. **Не раньше следующего дня:** добавь изменённый `README_START_HERE.md` и `ПОДГОТОВКА_К_ЗАЩИТЕ.md`. Commit message: `Добавлена инструкция запуска и описание программы`. Нажми **Commit** и **Push origin**.
5. **Ещё позже (отдельный день):** добавь папку `tests` и итоговый отчёт. Commit message: `Добавлены проверки и отчет по лабораторной`. Сделай **Commit** и **Push origin**.
6. Проверь на странице репозитория, что видно **3 коммита с реальными датами**, и скопируй адрес репозитория в раздел «Ссылка на репозиторий» отчёта.

Это пример нормального графика. Если коммиты будут идти подряд за пять минут, методичка не засчитает их разнесёнными во времени. Даты коммитов подделывать не нужно.

**Не загружай** файлы из `build`, `bin`, `obj` и созданные личные данные `*.dat`. Они уже исключены в `.gitignore`.
